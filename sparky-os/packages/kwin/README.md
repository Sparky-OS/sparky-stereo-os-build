## A network screen is a screen like the others (+stereo3d66)

`prepare-source-66.sh STAGED_65_DIR OUT TOOLKIT` takes the staged +65 source (row 862's stage) and adds four edition patches and one catalogue patch for queue row 81 (Throw to a Cast device).
s66-0001 adds the tests, red on +65: `networkedOutput` and `networkedChoiceKeptByIdentity` in test_virtual_output_properties, `testNetworkedOutput` in screencasting_test (every format the output offers, with and without its eye swap, and 2D) and the integration test testThrowToMenu.
s66-0002: an output the screencast protocol's version 7 request makes without the split-eye flag (`networked`, a Cast device) gets the VirtualStereo and StereoSwapEyes capabilities, so Display Settings offers its "Anaglyph" and "Other stereo formats" switches and its eye swap as for a monitor; `VirtualOutput` and `DrmVirtualOutput` make the format twins of its 2D mode from those switches (side by side half and top and bottom, the two anaglyph twins), it arrives in 2D at the device mode, and the configuration store gives back the format, switches and swap the person chose for that device (by its name, the protocol's persistent identifier) when the saved mode is a twin of the device's current mode.
The headset's split-eye outputs keep every row they had.
s66-0003: the stream of such an output in a 3D format is that output's picture: each eye drawn at the device raster, squeezed into its half for side by side half and top and bottom, mixed with the Dubois matrices for the anaglyph twins (one copy now, `opengl/anaglyphmatrix.h`, which the DRM layer uses too), the eyes in the order its swap gives; in 2D one view, as before.
s66-0004: the window menu keeps "Move to Screen" for the computer's own screens and lists networked outputs under "Throw to" by their device names (the protocol's description); `kwin-throw-to-menu.po.patch` gives "Throw &to" in the nine catalogues by the names rule.
`build-66.sh` takes build-65.sh's seven arguments with the staged +65 binaries as PREVIOUS_DIR and an empty PREVIOUS_SIBLINGS_FILE; testThrowToMenu joins `test-in-container.sh`'s list.
testScreencasting needs a PipeWire and a WirePlumber of the container's own and is run apart from that list.
For the next rebase: upstream KWin's !10355 ported the screencast plugin away from OpenGL and !10427 (open) lets only the creating stream resize a virtual output; s66-0003 meets the first.

## A window that went with Xwayland (+stereo3d65)

`prepare-source-65.sh PUBLISHED_64_DIR OUT TOOLKIT` takes the published +64 source (r1123a) and adds three edition patches for queue row 862, a station where every selected window stayed translucent after Xwayland died. s65-0001 adds testTranslucencyXwayland and a check to testXwaylandServerCrash (both fail on +64). s65-0002: `Workspace::removeWindow()` makes "no window active" through `setActiveWindow(nullptr)`, so `windowActivated(nullptr)` reaches effects and scripts when the active X11 window goes with Xwayland (the shutdown path of `cleanupX11()` skips `activateNextWindow()`); the translucency effect forgets a deleted window and handles the newly active window before the previous one. s65-0003: when KWin finds the X11 connection broken it keeps one notice in the person's store of sparky-stereo-problems (messages LOCAL5 to LOCAL7 in `stereo-replica-lang`, ten languages, `--subject LOCAL5=LOCAL6` in `rules`); the notice stays until the person dismisses it, a later stop replaces it, and the engine is not called at KWin's start (such a call moved which of Xwayland's death signals KWin read first: testXwaylandServerRestart failed 4 runs in 5). `build-65.sh` takes build-64.sh's seven arguments with the published +64 binaries as PREVIOUS_DIR; its PREVIOUS_SIBLINGS_FILE lists only edition packages this build needs that are not published yet (none for +65: an empty file), since the build's own packages are already the gate's inputs and a second version of one of them stops it ("conflicting supplied package: kwin-common; provide one authoritative edition snapshot"). The build image needs the repository key in `/etc/apt/trusted.gpg.d/sparky-stereo-repo.asc` and a user with uid 1000. The new tests join `test-in-container.sh`'s list.
