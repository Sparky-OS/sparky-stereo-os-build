kwin (4:6.7.4-2+stereo3d36) unstable; urgency=medium

  * Sparky-OS/kwin stereo3d36 is stereo3d35 plus the two commits of ORDER 257
    milestone 4 (s36-0001 and s36-0002) and the software twin's fix of
    milestone 4b (s36-0003).
  * DisplayPort frame sequential stereo, an output filter (s36-0001): the
    source sends one eye per frame of the mode and tells the display which
    eye each frame carries (MISC1 bits 2:1 of the Main Stream Attribute,
    DisplayPort 1.1a). KWin hands the kernel the full side by side frame of
    both eyes, left eye first, twice the mode's width, with
    DRM_MODE_FLAG_3D_FRAME_SEQUENTIAL (defined here until libdrm has it);
    the kernel alternates the halves and signals the eye. A mode the display
    declares is one of its 3D modes; elsewhere a 2D mode at 100 Hz or more
    gets a twin under Other stereo formats only where a TEST_ONLY commit of
    the mode with the flag succeeds, so on a kernel or a connector without
    it nothing new is offered. KWin renders and commits pairs at half the
    refresh, the output's eye swap applies, and neither kind is ever chosen
    automatically. The output device interface sends the new mode flag from
    version 30, so the package builds against plasma-wayland-protocols
    1.21.0-1+stereo3d10 and stops on a protocol without
    stereo_sequential_displayport. KWin's software frame sequential twins
    stay as their own options. STEREO3D.md says it (s36-0002). Test:
    testMockDrmDisplayPortSequential.
  * KWin's software frame sequential twin is paced one frame at a time
    (s36-0003): with a predicted render time near one refresh the render
    loop went into triple buffering, so a held pair's re-commit landed two
    refreshes ahead with the eye chosen for the next one, and the twin could
    stay on one eye. DrmOutput::maxPendingFrames() gives 1 in the frame
    sequential layouts, and the render loop leaves triple buffering when
    the maximum is under 2, so every frame, a held pair's re-commit
    included, targets the next refresh. DisplayPort's frame sequential
    filter and 2D keep two frames. Test:
    testMockDrmFrameSequential::testHeldPairTargetsNextRefresh. The package
    builds without tests; the commits are listed for the source.
