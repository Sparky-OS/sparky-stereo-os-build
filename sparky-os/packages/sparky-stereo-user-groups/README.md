sparky-stereo-user-groups
Every desktop user gets the groups a desktop needs, without asking: games, dialout, plugdev, audio, video, bluetooth, netdev, lpadmin, scanner, kvm, libvirt, render and sambashare.
Daniel, 2026-10-10: "this is a pain all the time for users coming from windows, where they don't even know this type of thing exists".

The three ways a user is made
-------------
One list, /etc/sparky-stereo/user-groups (a conffile; one group per line, comments allowed), feeds every way:

| Way | Where the groups go | Why it works |
|---|---|---|
| adduser | `EXTRA_GROUPS` and `ADD_EXTRA_GROUPS=1` in a marked block at the end of /etc/adduser.conf | adduser reads one file, the last assignment wins |
| System Settings, Users page | the same block | Debian's AccountsService (23.13.9-8) creates accounts with `/usr/sbin/adduser --add-extra-groups`, not useradd, so it reads adduser.conf; measured in a container |
| The installer (Calamares) | /etc/calamares/modules/users.conf, generated from /usr/share/calamares/modules/users.conf with the groups added to `defaultGroups` (`must_exist: false`, `system: true`) | Calamares reads /etc/calamares/modules/users.conf (tested with the real binary: a broken file there is noticed); the generated file is marked, regenerated by a dpkg trigger when the calamares package changes the shipped one, and a users.conf of the administrator's own is never overwritten |

`sparky-stereo-user-groups apply` writes all of it, `remove` takes it out (the package does this on removal), `status` shows it.
Plain `useradd` (a root shell) is not covered: it is the low-level tool and the person using it chooses.

The groups, and why
-------------
Each group is in the list only because a package the edition installs or recommends needs it.
Where a group exists only when its package is installed (libvirt, sambashare, scanner, bluetooth, lpadmin), a new user is added when the group is there; adduser prints a warning for a group that does not exist yet and goes on.

| Group | What it grants | Needed by |
|---|---|---|
| games | write access to a sim rig's tuning knobs (range, gain, display, LEDs): the rules of hid-fanatecff chown them to `games`; also the score files of sgid games | the sim-rig drivers of sparky-stereo-hardware, `joystick`, the games lists |
| dialout | full access to serial ports (base-passwd) | Arduino, ESP32, USB serial adapters |
| plugdev | access to removable devices and cameras in limited ways (base-passwd) | libgphoto2's rules (60-libgphoto2-6t64.rules), usbmuxd (iPhone over USB, its postinst) |
| audio | audio devices (base-passwd); the edition's 99-sparky-audio.rules puts cpu_dma_latency, rtc0 and hpet in it | PipeWire real-time work, audio tools |
| video | video devices: cameras, capture cards, DVB, CEC (udev's 50-udev-default.rules) | cameras, capture, HDMI-CEC |
| bluetooth | talking to bluetoothd on D-Bus (bluez's bluetooth.conf) | Bluedevil, bluez |
| netdev | network settings without a password (NetworkManager's polkit rule `isInGroup("netdev")`) | NetworkManager |
| lpadmin | adding and changing printers (CUPS `SystemGroup root lpadmin`) | cups, print-manager |
| scanner | scanners (SANE's 60-libsane1.rules) | sane-utils, Skanpage |
| kvm | /dev/kvm (udev's 50-udev-default.rules) | the stereo VM, Karton, virt-manager |
| libvirt | the system libvirt (libvirt's polkit rule `isInGroup("libvirt")`) | virt-manager, the stereo VM |
| render | GPU render nodes /dev/dri/renderD* (udev's 50-udev-default.rules) | GPU compute (ROCm, OpenCL), Vulkan without a seat |
| sambashare | the usershares directory of Samba (`install -d -m 1770 -g sambashare`, samba.postinst) | kdenetwork-filesharing: sharing a folder from Dolphin |

Debian's meaning of each group is in base-passwd's users-and-groups document (/usr/share/doc/base-passwd/users-and-groups.html).
libvirt and kvm let a person start virtual machines with the host's devices; Daniel listed them, they stay on the list and are flagged for his decision.

Never added
-------------
`apply` and `check` refuse a list that names any of these, and a group whose gid is 0:
root, adm, admin, disk, docker, input, kmem, lxd, operator, podman, shadow, staff, sudo, sys, systemd-journal, tty, wheel.
They equal root (docker, disk, staff, lxd, podman, sudo, wheel), read every keystroke (input, tty), the password hashes (shadow) or every log (adm, systemd-journal).
The installer's first user is the administrator and gets Sparky's own sudo and wheel from the calamares package; that is not changed here.

Existing users
-------------
Nothing changes for them, on install or ever.
`sparky-stereo-user-groups propose` prints the `usermod -aG` line each local user would need and runs nothing.

Why membership and not pam_group
-------------
pam_group (/etc/security/group.conf) would give the groups only to logins on the seat.
It was left out: polkit's `isInGroup`, CUPS's `SystemGroup` and Samba's directory modes read the account's membership in /etc/group, not the groups of a login process, so lpadmin, netdev, libvirt and sambashare would still say "permission denied" on a seat login.
The cost is that an SSH login of the same account has the same groups (tested), which is what a Debian installer does for its first user too.
