mpv-dmo (1:0.41.0-dmo9+stereo3d12) unstable; urgency=medium

  * Give a client of the render API one view of a 3D video per render call: MPV_RENDER_PARAM_STEREO_VIEW with an mpv_render_stereo_view (patch 0064, row 137). mpv_render_context_get_info() says whether the frame holds two views and the size to give the target of one view so that it is not resized on its way to the compositor; mpv_render_context_render() with view 1 or 2 draws that view alone, the on-screen display once per view at the same place. A client that does not pass the parameter gets the frame as it is, exactly as before: nothing changes for mpvqt and Haruna or for mpv's own windows. The value is outside the sequence of mpv_render_param_type so that it cannot meet a value upstream adds later; libmpv gains no symbol and loses none. Upstream has no such parameter (mpv master, pull requests and issues searched on 2026-11-25); Celluloid +stereo3d1 is its first client.
  * libmpv-dev depends on libmedia-gpu-route-dev and libstereo-av-dev: mpv.pc lists both libraries in Requires.private, and without their development packages `pkg-config --cflags mpv` failed ("Package 'media-gpu-route', required by 'mpv', not found"), so a program could not be built against libmpv-dev alone (found building Celluloid, row 137).
