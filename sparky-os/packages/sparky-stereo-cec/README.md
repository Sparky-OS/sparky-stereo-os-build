Build:
-------------
OUT=/path/to/workspace/pending-pack ./build.sh

Build in a Debian testing container as an unprivileged user, with at most
four CPUs. Development dependencies are in the generated source control.
The script builds a binary .deb and unsigned native .dsc/.tar.xz. Runtime
library versions are generated by dpkg-shlibdeps. Tests are separate.
For extracted SDK libraries set CMAKE_PREFIX_PATH, SHLIBS_DIRECTORY and
SHLIBS_FILE to the extracted prefix and the official DPMS shlibs file.

Install:
-------------
su
OUT=/path/to/packages ./install.sh

Uninstall:
-------------
su
./install.sh uninstall

Use:
-------------
The helper starts through /etc/xdg/autostart only in KDE. Its own guard also
requires a KDE Wayland session before initializing Qt, then requires the
Wayland platform. It creates no window and requests no output power change.
The logind session must also be active. Its GetSession lookup follows KWin's
XDG_SESSION_ID/auto selection. An inactive or unknown session sends no CEC
commands; queued work is cancelled when the session loses activity. This
prevents background Plasma idle events from sending TV commands on a console.
It observes KScreen's native per-output DPMS notifications, as used by
PowerDevil. There is no second idle timer, screen locker or console command.
X11 is outside this helper's scope: KScreen's X11 backend does not expose
these mode notifications and its constructor changes X11 DPMS timeouts.

A matched HDMI screen entering Off, Standby or Suspend sends Standby to TV
logical address 0. Returning On sends Image View On to that TV. Initial On
sends no wake message. Duplicate off states send nothing. The helper never
broadcasts Standby and does not change the TV's active input.

Discovery prefers CEC_ADAP_G_CONNECTOR_INFO's DRM card/connector identity.
The connected HDMI connector must match exactly one Qt screen name. Without
kernel connector metadata, one adapter and one connected HDMI screen can be
paired automatically. Ambiguous USB cases need an explicit binding in the
user's ~/.config/sparky-stereo-cecrc (or system /etc/xdg file):

[Adapters]
cec0=HDMI-A-1

This identifies the adapter connected to that screen's TV; the USB bus itself
cannot establish that cable association. Bindings do not override an adapter's
native DRM connector identity. Duplicate screen names are skipped. Adapter
numbers can change after reconnecting: review the binding if they do.

Unconfigured adapters claim a playback address through cec-ctl. For USB
adapters that allow setting their physical address, cec-ctl reads it from the
matched connector's EDID. An existing non-playback logical address is left
alone. No input daemon or remote-control passthrough is enabled by this helper.
The udev rule grants the active local user access to CEC nodes through
logind's uaccess mechanism, without running the helper as root. It takes
effect on the next device add/login; installation runs no live udev trigger.

cec-ctl is serialized per adapter, bounded by ten seconds and checked for a
verbose Tx, OK report. Exit zero alone is insufficient: cec-ctl also returns
zero for some unconfigured/failed transmissions. A missing adapter, unusable
address, missing executable, timeout or NACK cannot be reported as success.
The transmit source is explicitly a claimed playback logical address, even
when the adapter also has another logical address.
Failures are logged in English. Device hotplug is monitored, not polled.

Tests:
-------------
See ../../power-idle/CEC.md for the container commands, native protocol and
wire-byte assertions, and the written vivid kernel-framework procedure.
Tests do not access any real CEC adapter, display, TV or host session.
Actual TV firmware, cable association, driver HPD behavior and physical
standby/wake still require hardware verification. If the TV drops HDMI/CEC
when powered off, or the kernel invalidates its address, wake can fail; the
helper logs it rather than claiming success.
