Files:
-------------
/etc/apt/sources.list.d/sparky-stereo.sources: the edition's repository, https://repo.sparkyos.org/, codename mashtabba.
/etc/apt/sources.list.d/sparky-stereo-deb-multimedia.sources: deb-multimedia (forky), the base of the edition's FFmpeg and mpv.
/etc/apt/preferences.d/sparky-stereo: the edition's packages at 1001, Bino only from the edition, deb-multimedia's own keyring preferred, and the edition's carried NVIDIA 580 user space at -1 until one of the two NVIDIA driver locks (sparky-stereo-nvidia-driver-lock, sparky-stereo-nvidia-legacy-580xx-driver-lock) raises it: Hardware Setup installs the lock of the driver it chooses first, and a person who wants the 580 packages by hand installs the legacy lock first.
/etc/apt/preferences.d/sparky-stereo-only-ours: the block list, generated by apt/make-only-ours.py from the repository index: Debian's and deb-multimedia's builds of every package the edition ships at -1, so only the edition's builds are candidates, and their i386 builds of a program or library the edition ships for amd64 only, so apt does not list them; the packages the repository carries that are not the edition's (NOT_OURS in apt/make-only-ours.py) are not blocked, and the edition's copy ranks under theirs.

/etc/apt/apt.conf.d/60sparky-stereo-appstream-icons: enables AppStream's five DEP-11 icon targets for all repositories that advertise them, so Discover and KRunner can show cached program icons, including on HiDPI displays.

/etc/apt/apt.conf.d/00sparky-block-plain-http: no longer shipped. Versions 20261104.2 and 20261104.3 refused every plain http:// apt source with it; this version removes it (see "Plain HTTP was refused for a day" below).

The four source and pin files are conffiles since 20261031.1~sparky9~0; the icon setting is a conffile since 20261102.1~sparky9~0.
Purge removes these conffiles.
Debian Policy 10.7.3 says: "local changes must be preserved during a package upgrade", and "The easy way to achieve this behavior is to make the configuration file a conffile".
Before that version dpkg replaced them at every upgrade, a person's changes included.

What an upgrade does:
-------------
A file you did not change is updated without a question.
A file you changed is kept, and dpkg asks what to do: the default (N, or Enter) keeps your file, and the new one is saved beside it as FILE.dpkg-dist.
Without a terminal, dpkg cannot ask: the upgrade stops at the question, the package stays unconfigured, and your file stays as it is.
Run dpkg --configure -a at a terminal to answer, or dpkg --configure -a --force-confdef --force-confold to keep your file.
An upgrade run with -o Dpkg::Options::=--force-confdef -o Dpkg::Options::=--force-confold, the usual way to upgrade without a terminal, keeps your file and saves the new one as FILE.dpkg-dist.
The first upgrade to 20261031.1~sparky9~0 or later does the same: its preinst compares each file with what the installed version shipped (its md5sums), sets the unchanged ones aside so dpkg installs the new ones without asking, and leaves a changed one where it is, so dpkg asks about it.
A file you deleted before that first upgrade comes back once, since the older versions did not mark it as yours; after it, dpkg keeps a deleted conffile deleted.

Plain HTTP was refused for a day, and is not any more (ORDER 400, 2026-11-04; ORDER 413, 2026-11-06):
-------------
CVE-2026-109518 (Debian DSA-6607-1, found by Max Justicz; APT's announcement https://lists.debian.org/deity/2026/11/msg00005.html): with Acquire::Retries set (apt's default since 2.3.2), redirects and transient HTTP server errors let an attacker on the network path make apt overwrite a verified .deb with a chosen payload, which runs as root. The fix is in apt 3.3.6, which is in Debian testing now.
Daniel, 2026-11-04: "change them to https", then "block http sources for now". Versions 20261104.2 and 20261104.3 did both; the block was announced as temporary.
This version Depends on apt (>= 3.3.6) and removes the block:
- /etc/apt/apt.conf.d/00sparky-block-plain-http (it set Acquire::http::Proxy to a name that cannot exist) is removed on upgrade with dpkg-maintscript-helper rm_conffile (dpkg-maintscript-helper(1): "If a conffile is completely removed, it should be removed from disk, unless the user has modified it. If there are local modifications, they should be preserved."). A copy you changed is kept as 00sparky-block-plain-http.dpkg-bak, which apt does not read; the screen says which of the two happened and why.
- The change of http:// to https:// stays: on every install and upgrade the postinst turns plain http:// into https:// in /etc/apt/sources.list, /etc/apt/sources.list.d/*.list and /etc/apt/sources.list.d/*.sources, in the lines that are not comments. Each file it changes is copied first to /var/backups/sparky-stereo-apt/<UTC date and time>/<the file's path>, and the screen names the file and the copy. The edition's own files already use https and are not touched. This is a change to files other packages or you wrote (Debian Policy 10.7.4 gives a shared configuration file one owner); it is done because it was asked for, it is said every time, and the copy keeps your original.
- A source whose server has no HTTPS fails at apt update with apt's own error. Nothing turns it back to http:// and nothing hides the failure.
To see what was changed: ls -R /var/backups/sparky-stereo-apt. A plain http:// source you add yourself works again, with apt 3.3.6.

Keep your own pins in your own file:
-------------
The block list, sparky-stereo-only-ours, changes whenever the repository gains or drops a package, so a change made in it means a question at every such upgrade, and your copy no longer follows the repository.
Put your own records in a file of your own instead; the package never touches it.
apt_preferences(5) says: "/etc/apt/preferences is parsed first, followed by the files in /etc/apt/preferences.d in lexicographic order", and "The first specific-form record matching an available package version determines the priority of the package version".
So your file must sort before sparky-stereo-only-ours: /etc/apt/preferences itself, or a name such as /etc/apt/preferences.d/00-local.
A file sorting after it, such as zz-local, changes nothing for a package the block list names.
For example, to let Debian's krdc be installed instead of the edition's, on amd64:

    Package: krdc:amd64
    Pin: release o=Debian
    Pin-Priority: 500

    Package: krdc:amd64
    Pin: release o=Sparky Stereo OS
    Pin-Priority: 100

The first record lifts the block on Debian's build.
The second ranks the edition's under it: without it the edition's build, at 1001 (sparky-stereo), stays the candidate.
A name in a pin matches the native architecture only unless it says otherwise ("By default, only packages of the native architecture are matched", apt_preferences(5)): write krdc:i386 for the 32-bit package, or krdc:any for every architecture.
apt-cache policy krdc shows the priorities apt gives each version.
Remove your file to go back to the edition's builds.
Debian's and deb-multimedia's builds have none of the edition's stereo 3D changes.
