# ParaView and VTK in stereo (ORDER 50, step 5)

The proofs of the vtk9 and paraview recipes (`sparky-os/packages/vtk9`, `sparky-os/packages/paraview`), run in throwaway containers on a virtual Stereo KWin; nothing reaches a desktop.

## vtk-quad-buffer-blit

A program with no ParaView: a `QVTKOpenGLStereoWidget` in Crystal Eyes stereo draws a turning cone for 60 frames, and VTK's `Error in cache state for GL_DRAW_BUFFER` warnings are counted through the output window's `WarningEvent`.
Exit 0: a stereo context and no such warning; 1: warnings (the count is printed); 77: the window got no stereo context, so nothing was tested.
Build it against Debian's `libvtk9-dev` and `libvtk9-qt-dev` (`cmake -S . -B build && cmake --build build`); run it inside a Stereo KWin session (`rig/qb-case.sh`).
On Debian's vtk9 9.6.2+ds-3 it fails on both routes and both cards; on the edition's 9.6.2+ds-3+stereo3d1 it passes.

## rig

The lane's rig, with its paths (`S`, the lane scratch; `L`, the lane folder with its Docker socket) set at the top of each script; copy them and change those two lines to run them elsewhere.

- `make-rig.sh`: the rig image from `debian:testing` (by digest) with the published tree at pin 1001 and Debian's paraview; `make-green.sh` adds staged packages through apt from a flat repository (`flat-index.py`, Origin "Sparky Stereo OS"), keeping apt's plan; `make-review-images.sh` makes every image of the review from the stage.
- `run-case.sh NAME IMAGE CASE.sh VAR=value...`: one fresh container and Stereo KWin session per run (`session.sh`); `GPU=nvidia` for the RTX 3060 through CDI with the session's zink route.
- `pv-case.sh`: ParaView with the two-square fixture `two.vtk` (options `PV_STEREO`, `PV_SETTINGS`, `PV_EXTRA`, `MENU=1`, `MENU_KEYS` for a View menu action); writes the log, the draw-buffer warning count, the declarations, KWin's window list, the loaded VTK libraries and two captures; `pv_analyze.py` measures the pair against VTK's closed form.
- `pv-refuse-case.sh`: each former output type on the command line, in the language of `LANG`.
- `pv-settings-case.sh`: Edit > Settings..., its Render View tab searched for "stereo", then the Properties panel searched for it (`PV_ARGS` passes ParaView options; `OPEN_COMBO=1` opens Debian's Stereo Type list). The dialog is driven by keys only: clicks inside it did not land where the capture shows them, while clicks in the main window did.
- `vtk9-after.sh`: after the vtk9 build, its stage, comparison, tree removal, the paraview build, the green image and rows.
- `pv-after.sh`: after the paraview build, its stage, comparison, tree removal, the green-pv image, the edition ParaView's rows, the upgrade simulation and `view_equal.py`'s render-view comparisons (Debian's mono start against ours, Enable 3D off against Debian's mono, same route each).
- `disk-guard.sh`, `vtk9-space.sh`: the vtk9 build's room on /mnt/games: the guard pauses the build under 2.5 GB free; the watcher removes the object files once `override_dh_auto_install-arch` starts (no later step reads them: `CMAKE_SKIP_INSTALL_ALL_DEPENDENCY=ON`, one Python) and the rest of the build tree once `dh_install -a` starts.
- `pv-savestate-case.sh`: Debian's ParaView in Anaglyph saves its own state (`anaglyph.pvsm`, the old-state fixture: File > Save State is Alt+F, S; Ctrl+S is Save Data).
- `pv-gdb-case.sh`, `pv-gdb-trace-case.sh`: ParaView under gdb (image with gdb and paraview-dbgsym): the backtrace of a crash; each call of the functions in `TRACE`, with a time stamp and `BT` frames.
- `pv-notice-case.sh`, `notice_probe.py`, `notice-probe-case.sh`: KWin's window list every 3 s after ParaView starts (where the told-once notices are), and a PyQt6 probe of a window-modal box opened before and after its main window shows.
- `pv-after2.sh`, `pv-after3.sh`, `pv-after4.sh`: the chains after ParaView's rebuilds with patch 0003 (its three forms; the last is the staged one).
- `pv-noareas-case.sh` (as `SESSION=`): ParaView on a bare X server (no compositor, no stereo announced), captured through X (`xshot.py`).
- `red-batch.sh`, `qb-batch.sh`, `g3-batch.sh`: the red rows (Debian's packages), the reproducer's rows, and the edition ParaView's rows.
- `c2-build.sh`, `c2-rows.sh`: continuation 2: the three successors with kcmshell6 and KScreen's page as Depends (paraview +stereo3d2, jmol +stereo3d3, stereo-matplotlib 0.1.2), staged and compared, then their review images and rows: the display page from each program (`MENU_KEYS` in `pv-case.sh`, `ACT_KEYS` in `jmol-menu-case.sh`, `ACT=display` in `mpl_case.py`), the start after Enable 3D is changed and ParaView quit (`pv-restart-case.sh`, `QUIT`, `PV_KEEP_SETTINGS`), an old screenshot stereo mode under pvpython (`pv-shot-case.sh`, `pv_shot.py`), the old-setting and old-state notices on xcb and the RTX 3060, two translated sentences on screen.
- `ks-case.sh`: KScreen's page started directly, plainly, with `QT_QPA_PLATFORM=xcb` for the whole session, or for kcmshell6 alone (`KS_XCB=1`): on xcb its X11 backend aborts inside a Wayland session.
- `vtk-native-colour-size/`, `colour-size-shim/`, `cs-case.sh`, `cs-batch.sh`: VTK's colour-size warnings on Wayland: a mono QVTKOpenGLNativeWidget reproducer (exit 1 with warnings) and an LD_PRELOAD shim over `vtkOpenGLRenderWindow::GetColorBufferSizes` (`COLOUR_SIZE_SHIM=probe` prints the state at the call, `fix` applies the drafted rule), on Debian's vtk9.
- `menu-act-batch.sh`: the View menu's two edition actions in English and pt_BR (xcb): "Enable 3D" and its restart notice, "3D display settings..." (KScreen, or its sentence when it cannot start).
- `compare-debs.py`: a package against the one it replaces, file by file (paths, owners, modes, bytes; Lean Code projections checked against the manifest's `sha_hr`; ELF NEEDED, SONAME and defined dynamic symbols; control fields).
- `stage.py`: a source closure (the `.dsc` and every file it names, the `.changes` and every file it names, the build record, the log) with `SHA256SUMS`.
- `run-recipe.sh`, `make-builder.sh`, `archive.json`: the builds, with the temporary folder and the link gate's scratch inside the build folder. The builder's apt reads its certificates from `/run/host-ca.crt`: pass `EXTRA_MOUNTS="-v /etc/ssl/certs/ca-certificates.crt:/run/host-ca.crt:ro"` whenever `PRE` runs apt.
- `apt-upgrade-sim.sh` (`IMG` for the image it starts from; `apt-upgrade-why.txt` keeps apt's reason when the three paraview packages are held): every architecture-dependent package of Debian's vtk9 and paraview installed on the published tree, then the stage added and `apt-get -s full-upgrade` (Inst, Remv, Conf lines).
- `vtk-progs-batch.sh`, `prog-case.sh`, `prog_analyze.py`: each edition program that loads vtk9 (F3D published and staged, the model viewer, the Plasma theme studio, FreeCAD) started on Debian's vtk9 and on the edition's, its window's content measured and the two compared.
- `i6-batch.sh`, `i6-batch2.sh`, `i6-final.sh`, `jmol-case.sh`, `jmol-menu-case.sh`, `mpl-case.sh`, `mpl_case.py`, `jmol_analyze.py`, `mpl_analyze.py`, `i6/`: Jmol's and the plot module's rows in other languages (row 50 step 5, item 6): the pair, the told-once sentences, the loaders of all eight languages, Jmol's Display menu over its 3D area.
- Continuation 3, a rig that does not depend on the day (`rig/SNAPSHOT.md`): `prelude.sh` takes Debian testing from snapshot.debian.org at 20261119T023717Z (the index of the published tree's day; `Check-Valid-Until: no` on those sources alone), deb-multimedia from its frozen signed index in the lane's scratch (`freeze-dmo-index.py`: the InRelease checked with gpgv, every index checked against it; `freeze-dmo-pool.sh`: the pool files the rig's real install sequence fetched, each checked against the index), libstereo-declare 1.12.1 from frozen copies pinned at 1002. `make-rig.sh` brings the base up to the instant and writes `apt-distupgrade-TAG.txt`; `make-review-images.sh [all | NAME...]` builds every image under `NAME-new`, moves the tags only when all are built, then removes each replaced image by its ID, and reuses a `NAME-new` of the same instant left by a run that stopped. `check-tree-whole.sh NAME SNAP|live` simulates each package of the published tree alone on an instant, `tree-refusal-causes.sh` names what apt finds no choice for. `run-recipe.sh` gives the Lean Code gate the same instant (`archive-snap.json`).
- `review_rows.py PREFIX [ROW...]`: every review row in one command (continuation 2's rows, the 23 edition rows, the red rows on Debian's packages, the two VTK reproducers, the mono views against Debian's, apt's upgrade plan on two images, every image's dist-upgrade on the snapshot), each in a fresh container and session under `runs/PREFIX-ROW`; it refuses a used PREFIX, pauses a running build, ends with `runs/PREFIX-table.txt` (row, expected, found) and exits 1 when a row is not as expected. The colour-size expectation follows the libvtk9.6 each image carries. `vtk9-s2-after.sh`: after the vtk9 +stereo3d2 build, its source closure staged, +stereo3d1 moved to `ref/`, both compared file by file, the build tree removed, the images that carry vtk9 remade and `pv2-ref` made for the red rows.
